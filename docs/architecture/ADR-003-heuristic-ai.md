# ADR-003 本地启发式 AI 而非 LLM

- **状态（Status）**：Accepted（已采纳）
- **主题**：对手 AI 的实现方式——采用本地规则 / 启发式，而非大语言模型（LLM）。
- **关联**：ADR-001（离线单文件）、ADR-002（内嵌数据）。

---

## Context（背景）

《职场营销博弈》是单机 PVE 博弈，8 名 AI 角色需要做出"选哪张情况牌的选项""夜间如何行动""联席会议投谁"等决策。我们评估了 AI 实现方式的约束与目标：

- **离线 / 单机**：产品要求双击 exe 即玩、无网络（ADR-001），AI 不能依赖云端 API。
- **隐私 / 合规**：玩家对局数据不应外传。
- **零运行成本**：不应有按调用计费的 API 开销。
- **确定性与可控难度**：需要可种子复现、可用 tuning 调节 easy / normal / hard。
- **可调试**：博弈逻辑需可测试、可平衡（见 `run_headless` 质量门）。

候选方案：

| 选项 | 说明 | 取舍 |
| --- | --- | --- |
| LLM（云端 / 本地大模型） | 用大模型生成决策或对话 | 需联网或沉重本地推理；不可离线单文件；成本高、不确定、难控难度、难测试 |
| **规则 / 启发式引擎** | 性格向量 + 效用函数 + 派系信任漂移 + 白盒投票权重 | 离线、确定、零成本、易调参、易测试 |
| 混合（RAG + 规则） | 规则为主、LLM 生成叙事 | 复杂度高、仍触及联网 / 成本，超出 MVP |

---

## Decision（决定）

采用**规则 / 启发式 AI**，全部实现于 `src/ai.py`，完全本地、离线、确定性：

- **性格向量**：每个角色有 `ambition / risk / loyalty / cooperation / guile` 等维度（`state.PERSONALITY_KEYS`）。
- **选牌效用函数**（`ai_choose`）：
  `u = 派系忠诚×本派收益 + 野心×声望×ai_aggr + 合作×盟友收益 − 风险×(压力+现金损失) + 基线(声望−压力/2)`，结果乘 `uniform(0.85, 1.15)` 扰动取最大。
- **夜间行动**（`night_actions`）：高层"识人"（把 belief 直接置为已知派系），其余做信任 drift（`uniform(−3, 3)`）。
- **投票权重**（`vote_target`）：白盒——投给最不信任且声望最高（威胁最大）的存活者。
- **确定性**：rng 由调用方（`engine` / `run_headless`）注入，种子可复现；难度经 `tuning.DIFFICULTY` 的 `ai_aggr` / `player_influence_bonus` / `player_stress_malus` 调节。
- **无 LLM、无网络、无运行时大模型依赖**，契合单文件离线发行（ADR-001）。

---

## Consequences（后果）

### 正面
- **确定、可控、零成本**：同一种子产出同一对局，便于测试与平衡；无 API 费用。
- **离线 + 隐私安全**：不联网、不出数据，天然满足单文件离线发行与合规要求。
- **易调试 / 易测试**：纯函数式启发式，`run_headless` 可直接做"不崩 + 收敛"质量门（`main.py --headless N`）。
- **难度可调**：通过 `tuning.DIFFICULTY` 即可调 AI 凶悍度与玩家起步优劣。

### 负面 / 风险
- **行为可预测、缺涌现叙事**：启发式对手可被玩家"摸透"规律；不具真正自然语言对话或复杂欺骗叙事。
- **平衡需人工调参**：当前随机策略质量门下"玩家几乎不会输（lose=0）"属已知平衡偏差（见 `main.py` 提示与 `tests/qa-plan.md` 引用），需 design / qa 复核权重与阈值。
- **演进空间**：若后续需更强对手或更丰富叙事，可**局部**引入本地小模型推理层（仍须保持离线 / 确定性约束），但本期不采用。
